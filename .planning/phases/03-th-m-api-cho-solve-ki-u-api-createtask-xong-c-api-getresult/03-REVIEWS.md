## Antigravity CLI Review

### Summary
The plan proposes a lightweight, dependency-free solution using an in-memory dictionary and a dedicated background asyncio thread. This correctly sidesteps Flask's synchronous request lifecycle blocking the AI solvers. However, it introduces significant risks regarding Python dictionary thread-safety during iteration and multi-process deployment compatibility.

### Strengths
- **Architecture Choice**: Using a dedicated background event loop with `asyncio.run_coroutine_threadsafe()` correctly solves the problem of Flask tearing down event loops after each request.
- **Simplicity**: Avoiding Celery/Redis keeps the setup trivial for local deployments.
- **Lazy Cleanup**: The `cleanup_expired_tasks()` mechanism is a simple way to implement TTL without complex timers.

### Concerns
- **[HIGH] Multi-Process Deployment Failure**: In-memory `pending_tasks` are scoped to a single process. If the Flask app is deployed using a WSGI server like Gunicorn with multiple workers (e.g., `gunicorn -w 4`), a task created on Worker A will return 404 when `getTaskResult` hits Worker B.
  - *Mechanism*: Flask's global state does not share across processes.
- **[MEDIUM] Dictionary Iteration Thread-Safety**: The `cleanup_expired_tasks()` iterates over `pending_tasks.items()`. If the background thread adds or removes a task concurrently, Python will raise `RuntimeError: dictionary changed size during iteration`.
  - *Mechanism*: While the GIL protects internal C structures, it does not prevent a context switch during the `.items()` iteration.
- **[LOW] Flask Reloader / Global State**: Starting the thread in the global scope of `app.py` might cause it to be spawned multiple times if Flask's auto-reloader is active, or if imported multiple times.

### Suggestions
- **Locking**: Wrap operations on `pending_tasks` (especially `cleanup_expired_tasks` and deletion) in a `threading.Lock()` to prevent `RuntimeError`.
- **Deployment Constraints**: Explicitly document that this service must be run with a single process (e.g., `gunicorn -w 1 --threads 4`). If horizontal scaling is ever required, the storage must be migrated to Redis.
- **Thread Initialization**: Ensure `bg_thread.start()` is executed safely, perhaps checking if `background_loop` is already running to avoid duplicate threads during hot-reloads.

### Risk Assessment
**MEDIUM**. The plan is functionally correct for a single-process deployment, but the dictionary iteration race condition will cause intermittent 500 errors if a lock is not added.
